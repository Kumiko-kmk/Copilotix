# 界面偏好

## 全应用沿用文库风格

用户喜欢文库的视觉语言，但不要为模仿而堆叠线条与文字。设置、阅读器、问答与教程已对齐；新界面沿用：

- 层级：页面标题用 `PageBrand`（英文大写眉标＋粗黑标题，说明行可选，窗口高度 ≤760px 时隐藏），不要再叠加多余标签或提示文字。
- 分隔：靠留白与柔和的浅色面板（无边框、圆角 4px）区分区块；不加墨线、方点、虚线行分隔等装饰线。
- 控件：主按钮为墨色、悬停转强调色；分页签为灰字、选中墨字加强调色下划线；禁用按钮保持透明底。全局 token 在 `main.tsx` 的 `ConfigProvider`。
- 首页保留原有动态字标与书桌动态背景（漂浮纸张、视差、光点、上传卡光晕），只把主按钮换成墨色并让标题像文库解密那样从墨条下揭开；与文库的呼应靠动态美感，不靠线条。
- 拉丁文标题不用两端对齐（短行会被拉开），中文正文与文库区仍两端对齐。

## 设置页一屏显示，不出现滚动条

设置的三个分页在最小窗口 1100×700 内完整显示，不滚动、不裁切。每个服务（MinerU、DeepSeek、Qwen、Codex）占一行：名称与标签、凭据或程序栏、操作按钮、状态；Codex 的模型选择与说明只多一行。用量面板填满剩余高度并可压缩；模型优先级的请求顺序放在标题行，窗口高度 ≤760px 时行距收紧。新增服务或设置项须先确认仍可一屏放下，放不下时调整布局而不是加滚动。回归入口：`e2e/ui-chrome.spec.ts` 的两个设置用例在 1440×900 与 1100×700 检查内容不溢出。

## 文字两端对齐

文库（选中页、展示档案页、搜索结果、档案卡内容）的正文统一两端对齐：行尾整齐，逐行遮挡条也随之齐整。论文标题、译文标题与搜索结果标题左对齐（两端对齐会把短行拉开）。分类名、操作提示等原本居中的标签保持居中。

阅读器原文／译文正文、列表及 AI 问答的问题／回答正文同样两端对齐；标题、代码和表格沿用内容排版，不拉伸短标题或数据。

## 不显示悬停提示

用户不喜欢悬停说明，包括黑底白字提示、原生 `title`、Tooltip、Popover 预览和截断全文浮层。此规则适用于整个应用，不用换颜色或延时替代。必要信息放在页面内或由明确点击展示；保留可见标题、`aria-label`、进度、错误及操作确认。

唯一例外是用户 2026-10-17 明确要求的阅读器便利贴笔记：悬停在写了笔记的文字或页边羽毛笔上，约 0.2 秒后显示该笔记并可直接修改。它展示的是用户自己写的内容，不是说明文字；不得以此为先例给其他控件加悬停浮层。

## 已搜集并移除的位置

| 页面 / 区域 | 移除的提示 |
| --- | --- |
| 首页 | COPILOTIX 字标“点击重播”；继续阅读卡片的论文全名 |
| 文库选中页 | 论文标题、译文标题、关键词、总结、右下角分类全文 |
| 展示档案页 | 论文标题、译文标题、作者 / 单位、证据基础、检验方式的全文提示 |
| 阅读器 | 返回、重试、删除论文；分隔条拖动 / 双击说明、视图页签操作说明、关闭 / 恢复视图、滚动同步、还原分组、布局操作、PDF 无法复制说明、选区数量 Badge 提示 |
| 论文问答 | 固定选区的全文提示；服务商和模型的选中项 / 下拉选项自动提示；引用悬停摘录预览 |
| PDF 正文 | 悬停或选中区块时浮出的文本 / 图片 / 表格等类型标签 |
| 设置 | 活动热力图的日期、文档数、页数提示 |
| Markdown / HTML / 公式 | 显示层删除原文 HTML 和公式生成内容中的 `title` 属性，防止内容自带的提示出现 |

引用点击定位、论文打开、字标重播、阅读器布局与快捷键继续保留。PDF 合并标记为常驻状态信息，继续显示。

`Modal.title`、服务卡片 `title` 和表格列名为可见标题，保留。Select 与 Badge 的空 `title` 用于关闭组件自动提示，不能直接删掉，否则组件会以标签或数量重新生成提示。

显示层移除提示，不改论文原文、存储、导出或生成协议。
