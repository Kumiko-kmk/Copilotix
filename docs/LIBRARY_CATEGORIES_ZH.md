# 文庫內容分類

文庫按論文內容分類，每個分類只佔一列。Lite 版不在文庫列中使用，而是作為側欄分組（Lite 無檔案卡，命名只來自詞）：側欄只用分組與成員，組內按置頂再新到舊排列，詳見 [UI 偏好](UI_PREFERENCES_ZH.md#lite-版外殼)。

## 流程

1. **文字**：Utility 為每篇論文取代表性文字——標題加摘要、結論與資訊量最高的段落（`buildBriefContext`，standard 24 KiB）。有譯文時用譯文，使以中文閱讀為主的文庫在同一種語言中比較；尚無可讀文字的論文進入“待分類”。
2. **詞**：拉丁詞（≥3 字母）與 `Intl.Segmenter('zh')` 中文詞；去掉公式、LaTeX 命令與常見虛詞。詞頻按論文與文字修訂快取，只有內容變化的論文才重新讀取。
3. **相似度**：TF-IDF（次線性詞頻，僅保留至少兩篇共有、不超過半個文庫都在用的詞，每篇取前 200 個詞），經倒排索引計算餘弦，每篇保留最相近的 5 篇。
4. **分組**：在近鄰圖上做 Louvain 社羣發現，掃描解析度 0.5–4.0，按模組度選擇，並偏向約 √n 組（14 篇約 4 組，37 篇約 6 組）；孤立的單篇併入最相近的組。不足 4 篇或詞彙過少的文庫為一組“全部論文”，保持最新優先順序。
5. **命名**：組內論文有 AI 檔案卡時，取其“領域方向”（`field.area`），越典型的論文權重越高；沒有檔案卡時取組內多篇共有、最具區分度的兩個詞（c-TF-IDF）。名稱 ≤24 字，重複時加序號。
6. **排序**：組按大小，組內按與組中心的相似度（最典型在前）；每個分類只佔一列，按原順序迴圈瀏覽全部論文，不拆列或新增 1/2 字尾。

## 契約

- Core RPC `compute:library-categories`（compute 通道）與 IPC `library:categories`，`{ after? }` → `{ revision, categories, items ≤200, next }`；同一 revision 的後續頁直接讀第一頁算出的結果，renderer 遇到 revision 變化時重新讀取（最多 3 次）。
- 結果只在 Utility 記憶體中快取，不寫入文庫、不新增 migration 或備份項。論文增刪或狀態變化、檔案卡生成完成時，文庫頁（400 ms 防抖）重新請求；未返回前顯示一列“全部論文”，返回後場景保留當前選中論文。
- 不呼叫模型，沒有費用；檔案卡隻影響分類名稱，不影響分組本身。

## 已知侷限

- 詞頻相似不保證主題相同；檔案卡只改善組名，不修正誤分組。
- 新增論文可能使分組整體變化（列的順序與名稱隨之調整）；目前沒有固定或手動移動論文的功能。
- 中英文混合的文庫中，只有原文的論文與有譯文的論文較難歸到同一組。

右下角列數與分類數一致；分類名居中顯示，預留十二個漢字固定寬度，過長省略，左右箭頭位置固定。依使用者偏好不顯示懸停提示。
