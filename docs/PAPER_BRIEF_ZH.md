## 閱讀資訊

結構參考五 C、CARS、結構化摘要與論證模型，涵蓋研究問題、方法、證據、成立條件及閱讀建議；適用實證、方法、理論、系統、資料集、綜述、觀點、案例與質性研究。模型輸出簡體中文，欄位以 `shared/paperBrief/schema.ts` 為準。

## 摘錄與請求

- Utility 使用 `buildBriefContext`、detailed 預算 56 KiB（2026-10-10 前為 standard 24 KiB）。優先原文，缺失或空白才用譯文；正文不進 Renderer 再轉發模型。
- 移除圖片路徑、引用標記、長公式與無關章節，表格壓縮成文字。數學中的 `<` 不作 HTML 標籤；標題不依賴前後空行；排除頁首作者／授權資訊，但保留無摘要標題期刊的長段摘要回退。
- 按 IMRaD 角色、貢獻線索及數字密度選段；必選摘要／結論／貢獻，保底方法／結果／討論／局限，再按角色配額填充。單段上限 1100 bytes（摘要 3000、結論 2600、貢獻段 1400），最多 96 段，依原文順序編號 E1…，附目錄（≤3200 bytes）與覆蓋報告。56 KiB 是選段預算，序列化開銷另計。14 篇實測：每篇送出 26–59 KiB（原先約 24 KiB），短論文幾乎全文送出，完整請求 33–67 KiB。
- Main 使用 `buildBriefMessages`，將正文標為不可信資料；temperature 0.2、max_tokens 6000、JSON response_format；單次生成逾時 300 秒（原 180 秒）。ChatProvider 僅在服務商明確回覆可選參數不支援時省略並重送一次；問答原有預設不變。檔案卡使用非思考模式，避免思考內容耗盡結構化輸出額度。
- 包括修復對話在內，每次完整序列化 HTTP 請求 body ≤80 KiB。`parseBriefResponse` 失敗僅追加一次截短的 assistant 回答與具體欄位錯誤，重試仍須通過預算與授權檢查。
- 目前 `PAPER_BRIEF_PROMPT_VERSION = brief-v2.2026-10-10`：加大輸入、加入字數區間與更具體的寫作要求。後續修改提示詞、選段或欄位契約時須更新版本。真實 API 上的品質與字數達成率尚未重新驗收；費用約為原先的兩倍（輸入約 2 萬 tokens、輸出 3–6 千 tokens）。

## 校驗邊界

`assembleBrief` 將模型內容、程式 checks 與 provenance 合併後 strict 校驗。刪除不存在的 anchor、去重列表，閱讀路線只保留目錄中的章節；摘錄截斷或缺角色時強制標示依據部分摘錄。

`grounded` 只表示引用了存在的摘錄；`numbersVerified` 檢查 evidence 中的數字是否出現在引用摘錄或摘要包。它們不驗證推論是否成立、數字的單位／條件是否正確，也不證明論文結論可靠。未通過的發現保留並標示「需核對」，由讀者核對來源；強度是 AI 判斷。模型聲稱的局限與缺失資訊同樣需要人工判讀。

## 驗證與尚待驗收

- 單元與服務測試涵蓋選段、strict schema、48 KiB 預算、格式修復、checks／anchors 保存、v1／v2 共存、prompt 與 source 過期規則、取消等待與原子提交失敗；備份／卸載清單覆蓋 v2 與臨時檔。
- Electron 使用隔離文庫與 mock provider HTTP，驗證設定／憑據流程、四分頁、故意捏造的 99.7% 顯示「需核對」、摘錄展開、保存重開與自動生成設定。此為流程驗證。
- **真實 API（2026-10-09，使用者明確授權兩篇）**：DeepONet 與 AlphaFold 各呼叫 `deepseek-flash` 一次，無修復重試；共 14,939 input + 5,523 output = 20,462 tokens。結果保存至原文庫各自的 `insight/brief.v2.json`，可在打包程序中搜尋論文後查看。
- DeepONet：6 條發現，4 條數字檢查通過、2 條需核對，保存 12 個來源摘錄；AlphaFold：6 條檢查均通過，保存 8 個來源摘錄。兩篇都標示部分摘錄。這是生成／持久化與程式檢查結果，**不是跨學科人工品質評分**。
- 尚待使用者在打包程序驗收版面與內容；跨學科 10–20 篇人工評估（忠實性、具體程度、覆蓋、類型判斷、閱讀路線）仍未完成。本輪不擴大到全庫生成。

目前詳情分頁順序為「摘要 → 概覽 → 發現 → 局限與前提」。閱讀路線與術語不在文庫展示，生成提示詞及儲存欄位保持兼容。
